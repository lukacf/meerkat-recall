# Document embedding ownership

The generic document embedding loop serves documents whose source has no accepted source head. An existing physical source head reserves that document for the source-publication worker, which retains its original queue claim, immutable input manifest, approved profile and canonical publication fences. A completed, failed, superseded, malformed or foreign payload at the exact head identity does not return ownership to the generic loop.

Pending selection follows DocNode -> DocRevision -> Doc -> source and pages past managed nodes before applying the requested result limit. Named spaces use the same rule. Explicit generic chunk/exact-node entry points also refuse managed nodes before calling the provider. No source claim is synthesized or borrowed. Standalone documents, including retained source-linked documents without an accepted head, continue to embed. Existing missing-revision/dead-letter behavior is retained; a missing document is allowed only when no physical document exists at its global identity.

Generic vector/marker persistence captures the ownership links and checks them again in its transaction. An accepted head appearing after selection or during inference, a changed revision/document/source link, deletion, or a newly present previously absent document/revision refuses the write. Embedded storage holds its mutation lock; native storage checks exact records and writes the existing canonical epoch shared with migration 031 document, revision and source-head events. Dead-letter marker updates use the same ownership guard and update only the marker and timestamp. There is no new schema or durable authority.

This removes the background competitor for already source-managed nodes. It does not cancel provider work already sent before an unmanaged source is accepted, refund usage, coordinate standalone workers across processes, or provide a new immutable-text contract for all legacy document edits. Such a late acceptance still prevents unfenced vectors or markers from being committed. Source-fenced and reindex transactions retain their existing stronger authorities unchanged. Selection is retried on later loop passes; its in-memory pagination is not a durable checkpoint.

## Regression source

Four storage tests exercise both embedded and Surreal memory backends: pagination past managed/foreign/malformed heads; refusal of generic vectors and dead-letter markers while standalone writes succeed; atomic rollback when a head arrives after preparation; and changed links/deletion after preparation. Three pipeline tests use a recording fake provider through actual worker/storage entry points: zero calls for managed nodes, refusal of writes after acceptance during the provider call, and continued standalone processing. These sources require validation after integration; authoring them is not execution evidence.
