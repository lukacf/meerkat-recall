# Text renderer evidence coordinates

This is the normative source contract for `elephant.renderer.text`, version
`1.0.0`, with `config_hash: null`. It describes the active default renderer and
the shared mapper in `crates/types/src/rendered_text.rs`. It is a source contract,
not a claim that a particular runtime or consumer has passed qualification.

## Complete output

The renderer applies this exact Rust transform to the complete original UTF-8
text, in this order:

```rust
text.replace("\r\n", "\n")
    .replace('\r', "\n")
    .lines()
    .map(str::trim_end)
    .collect::<Vec<_>>()
    .join("\n")
    + "\n"
```

CRLF and lone CR therefore become LF. Rust `str::lines` splits the resulting
text at LF, excludes the separator, and does not append a final empty line just
because the input ends with LF. Interior and repeated trailing blank lines are
retained. Each line loses its trailing Unicode whitespace; leading whitespace
and interior whitespace remain. A literal LF is then placed between the lines
and one LF is appended at the end. This does **not** collapse multiple trailing
blank lines into one. U+0085, U+2028 and U+2029 do not act as line separators in
this transform; they can be removed by `trim_end` when at a line's end.

The current Rust Unicode `White_Space` set used by `trim_end` is U+0009-U+000D,
U+0020, U+0085, U+00A0, U+1680, U+2000-U+200A, U+2028, U+2029, U+202F, U+205F
and U+3000. A change to these observable transform semantics requires an explicit
renderer contract/version change; consumers must not silently substitute another
language's whitespace or line-splitting rules.

The active renderer rejects the exactly empty string before normalization and
does not produce a successful active revision for it. The pure normalization
helper's mathematical result for the empty string is `"\n"`, entirely generated;
that helper result is not a successful renderer output. Nonempty all-whitespace
input follows the transform, but generated-only output cannot ground a span.

## Origin of each rendered byte

All intervals are nonempty half-open **UTF-8 byte** intervals, `[start, end)`.
Both endpoints must be scalar boundaries and within the complete rendered text.
Coordinates are not character counts, UTF-16 offsets, line numbers or inclusive
end positions. Invalid intervals are rejected, never clipped or repaired.

Copied content bytes keep their exact original positions. A rendered LF that
corresponds to an original line terminator maps to that original terminator:
one byte for LF or lone CR, two bytes for CRLF. This remains true for the final
LF when the original input already has a final terminator. When the last line
has no original terminator, its appended LF is generated and has no original
byte origin.

The raw span is the smallest contiguous original interval covering all original
bytes that contribute to the selected rendered interval. Removed whitespace
between contributing bytes remains in this raw cover. Removed whitespace after
the final contributing byte is excluded unless a contributing original newline
follows it. A span containing only generated bytes is rejected. A span combining
real content with the generated terminal LF maps only the actual original
support. The exact rendered interval and digest still include that terminal LF.

| Original text (escaped) | Rendered text | Rendered span | Raw span | Raw quote |
|---|---|---|---|---|
| `A  \r\n` | `A\n` | `[0,2)` | `[0,5)` | `A  \r\n` |
| `A  \r\n` | `A\n` | `[1,2)` | `[3,5)` | `\r\n` |
| `A  \n` | `A\n` | `[1,2)` | `[3,4)` | `\n` |
| `A  \r` | `A\n` | `[1,2)` | `[3,4)` | `\r` |
| `A  ` | `A\n` | `[0,2)` | `[0,1)` | `A` |
| `A` | `A\n` | `[1,2)` | rejected | generated-only LF |
| `A\r\nA` | `A\nA\n` | `[2,3)` | `[3,4)` | second `A` |

These mappings are positional. Equal quote bytes at another occurrence never
select or substitute an origin. A valid newline coordinate does not by itself
establish semantic support for an assertion.

## Verification and its limits

The server recomputes the complete accepted raw input hash and compares it with
both original accepted source declarations. It independently recomputes the
complete immutable rendered revision hash. The mapper checks the complete
transformed output, exact renderer name/version/configuration, both UTF-8
boundaries and the original positional cover. The search consumer retains and
rechecks the same completed publication, source-to-revision mapping, evidence
and authorization before returning it. Unsupported renderer/configuration or
changed original inputs are refusals, not reasons to search for an equal quote.

A consumer independently checking raw coordinates needs the complete original
pushed raw text, bound to the expected source and external revision, or another
verified immutable binding to those exact bytes. The rendered revision alone
can verify a rendered slice/hash and renderer metadata. It cannot prove the
original raw cover, which equal raw occurrence was intended, or the current
accepted source/publication/authorization. A quote hash alone does not distinguish
equal occurrences or revisions that happen to render to the same text.

`elephant.renderer.passthrough` version `1.0.0`, `config_hash: null`, is supported
only as complete byte identity. Other renderers/configurations have no mapping
under this contract. The full immutable revision wire schema, evidence fields
and whole-response limits are specified by the API contract owner; a text mapper
does not replace those route or authorization checks.

The independent [passthrough literal fixture](../tests/recall_preview_semantics/passthrough-coordinate-fixture.json)
fixes original and rendered bytes `41c3a90d0ae78cabf09f9982` (`Aé\r\n猫🙂`)
before calling either implementation. Both contain exactly 12 UTF-8 bytes and
end with the emoji, without a generated LF. The quoted interval `[1,12)` has
the same raw and rendered bounds and contains the original CRLF. Literal SHA-256
digests cover the full inputs and both quotations. Its four negative controls
reject default normalization, an appended LF, a split UTF-8 code point and an
unrecognized renderer-name alias. Separate Rust source tests consume this same
packet through the actual passthrough renderer and the shared coordinate mapper;
the packet itself carries no publication or authorization proof.
