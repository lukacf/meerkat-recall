# Identity sweep preparation

Root delegated `crates/pipeline/src/maintenance/identity_sweep.rs` to this lane; maintenance owns the shared adapter, scheduling and final commit. This is active product source, separate from frozen D relevance expectations.

`prepare_identity_sweep` uses the caller’s original canonical epoch and overlay. Discovery pages the named space and applies prior creates/updates/deletes; the epoch fences that scan. Only selected pair, candidate and dossier snapshots become causal dependencies, so an unrelated discovery row does not grant or remove authority. Every selected pair is re-read after earlier merges; a staged redirect cannot merge again from a stale discovery clone. Dossiers use staged relationships, assertions, counterpart names and source metadata. Storage failures propagate; missing provider capability may skip a model-dependent pair without authorizing any mutation.

Candidates inherit both entities’ restrictions, subjects, completeness and source ownership, plus actual model context. Maintenance’s `stage_inherited` checks each contributing envelope against the actual observed/planned row and the storage owner’s monotonic inheritance rule; existing candidate and survivor restrictions can tighten without being reset to a default. The retained deterministic indistinguishable-entity shortcut does not require a provider. Model calls still use the existing governed identity dispatch and governed fallback. Neither controlled decisions nor deterministic matches constitute semantic-provider acceptance.

The shared identity `prepare_entity_merge_on_plan` owns alias/key/handle/metadata merging, all core and registered native extension references, redirects, merge lineage, audit and semantic outbox effects. The sweep preserves its previous maximum risk/trust and `known_safe` union before handing off. The complete prepared merge replaces the exact expected overlay via maintenance’s guarded `adopt_plan`, preserving original before images, dependencies, epoch and preceding effects. There is no nested canonical commit. The standalone public wrapper performs one final maintenance commit; the main maintenance path calls preparation and owns its larger single commit.

These tests are source only until central execution records an exact artifact and outcome. No model request is authorized by these tests.
