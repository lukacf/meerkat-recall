# Native reference-token HMAC state

The reference normalizer initializes HMAC-SHA256 once per extractor invocation,
including the existing v1 domain, journal identity and space prefix. Each
reference clones that owned state, appends the original typed table/identity
encoding, and finalizes its own clone. The extractor's prefix state is never
advanced by a reference and is discarded with the invocation.

This changes the cost of repeating the same HMAC initialization. It preserves
the v1 bytes and token format, typed UUID normalization, exact string and JSON
grammar, sorted token set, original errors, every node/depth/decoded-byte limit,
and traversal of duplicate references. There is no global cache, skipped
reference, change to key custody, or persisted MAC state. Encoders and traversal
functions are unchanged. Both public native token functions and the registered
SQL function use this extractor.

The actual R34 diagnostic on source `e4498116` recorded reference-token
extraction in eight of 37 snapshots from the thread with the largest preceding
CPU interval; three showed HMAC key initialization. This is sampled diagnostic
evidence, not exclusive CPU attribution or a performance result for this change.
The deliberately stopped diagnostic did not qualify the original 256/257-node
control, and its 240-second limit remains unchanged.

Two private engine controls retain the original whole-message HMAC algorithm as
an oracle across identities, errors, invocation order and store bindings, and
exercise duplicate node accounting plus depth/decoded-byte refusals. Two
workspace controls check independent fixed HMAC vectors through the public
identity function and the actual native SQL function with mixed, repeated and
reordered reference representations. The fixed vectors use Python's standard
`hmac`/`hashlib`, explicit big-endian length tags and the documented v1 encoding;
they are not generated by the candidate normalizer. Private controls are not
counted as workspace runtime coverage.

At the source checkpoint these Rust controls are authored, not executed. Runtime
equivalence and the original performance gate require centrally scheduled
validation of the coherent integrated source.
