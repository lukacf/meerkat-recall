# Independent contact lineage oracles

`contact_lineage_oracles.rs` is a D-owned child of F's
`bin/elephant-pipeline/src/work_item_tests/source_contact_finalization_tests.rs`.
F owns the module declaration and actual contact acceptance/worker fixture.
The child uses that fixture's real queue claims, support-verified interpretation,
embedding transport spy and whole-source finalizer. Its six asynchronous tests
and one future-size test are authored, unexecuted source; the module hook must be
joined before central compilation. No live-provider quality is claimed.

Each backend first publishes real structured contact effects and proves that its
evidence-free relationship has valid original contact support. An actual public
independent status edit must preserve that factual proof. Five corruption cases
then change only one private control payload: missing last-writer pointer,
unknown pointer, another real source's receipt, the stale original receipt, or a
cycle through two actual status transitions. The cycle's Active-to-Disputed and
Disputed-to-Active effects have compatible before/after facts. It cannot be
dismissed as an unrelated malformed relationship.

Every corruption must fail closed, retain the exact complete graph rows and
make no model request. Restoring only the original owned control payload must
restore the positive proof. Native and embedded edits are explicitly labelled
fault injection; they never establish a positive publication or support receipt.
Control keys are independently derived from the documented length-delimited
space/source/revision/record or space/commit identity. Actual private rows must
exist before alteration, and the resulting bytes are read back.

The same-revision test publishes contact R, then accepts a fresh explicit plain
intent for exactly immutable R with a new idempotency key and current CAS. It
requires a distinct actual operation/generation without changing the immutable
input. While the successor is pending, the older published contact proof remains
valid. After the actual plain successor publishes, that old relationship cannot
borrow its predecessor's contact seal merely because the revision label matches.
This does not assert that the old contact relationship survives plain publication.

F separately owns actual shared A/B inverse, independent status, physical receipt
purge, surviving admission, fresh retained reprocess and public supersession
positives. A owns codec/atomic pointer guards; M owns factual redirect predicates.
Their tests and these independent expectations must be joined coherently. No
historical proof may be reconstructed from timestamps or a matching fingerprint.

The destructive same-revision case starts from two actual independently admitted
A/B contacts with the same fact. Both original completed publications must prove
the shared relationship. Fresh plain B reuses the complete immutable B source
and revision but has a new operation/generation; the pending interval must still
prove original B. Its real completed finalizer must leave the independently
supported A relationship while removing B contact authority. Actual erase A must
then succeed and remove the contact entity/relationship and their support, while
B's complete immutable input and current head remain unchanged. This is stronger
than treating a refused erase as a negative success. The local spy must observe
no additional request during erase. Distinct original source rendition keys
respect the native per-space unique index. Both backend cases are unexecuted.

The separate storage child `source_lifecycle_contact_oracles.rs` now authors the
corrupt-survivor destructive boundary for both backends. E owns its minimal module
hook inside `source_publication_manifest_tests.rs`. It builds original sealed A,
B and foreign contacts through real acceptance, actual claimed fixed-metadata
work, the actual manifest repository and canonical finalization. It never writes
a fabricated Completed source/head/receipt or uses the parent's synthetic Done
origin helper. No Graph interpretation, full dispatcher or model quality is
claimed by this storage-composition fixture.

A valid A/B relationship first requires both actual original contact proofs. Only
B's real support pointer is changed to the genuinely committed foreign receipt,
whose effect set must exclude the shared relationship. Actual erase must return
`StorageError::Conflict("contact_survival_support_writer_changed")`, retain exactly
one original journal intent and leave Failed readiness with ordinary reads
refused. Under the existing private exclusive maintenance scope, raw physical
Entity/IdentityKey/Rel/Source rows including tombstones and all three original
canonical receipt payloads must equal their pre-fault values. B's head remains
unchanged; A's head must reflect the genuine pending Erasing reservation.

That same maintenance scope repairs only the injected support payload and calls
real `recover_pending_erasures` against the original intent before it may return
success. It must complete the original reserved operation, remove A support,
retain B's actual contact proof and preserve original journal identity. Normal
readiness becomes Ready only after that recovery. An inspection-only successful
barrier closure would wrongly clear Failed and is expressly absent. These two
new storage cases remain authored and unexecuted; they are additional independent
expectations, not a claim that physical rollback already passed.

The private-row helpers explicitly honor the kernel's fully qualified `table:key`
identity and 101-row page cap. They collect at most 256 original rows over bounded
cursor pages before selecting the exact control; a truncated first page cannot
masquerade as a complete inventory. Native `type::thing` still receives the bare
key. The storage-only Metadata case registers an explicit empty processing policy
with no connections or profiles, so token resolution is valid and no outbound
provider authority is created. These source corrections came from independent
A/F review before any execution of the new cases.
