# Generated definition read and withdrawal

A generated KnowledgeViewDefinition is readable only through its actual original
canonical decision: the exact stored output, original private receipt, SourceDecision
effect, original material dependency rows and current published source authority.
The provenance chain pointer only addresses that receipt. Missing or changed proof
cannot fall back to a source support ledger. Intrinsic direct configurations with no
computed extractor, work-run or chain keep the existing strict base-support path.
Hidden definitions are ineligible immediately after canonical withdrawal.

Every original input is authorized using its typed security view, including implicit
Entity self and relationship endpoint subjects, and processed by the existing current
read logic in the same ReadEligibility context. Traversal is bounded by the sealed original inventory's finite cardinality and
deduplicates physical IDs. Identity keys additionally require their actual Entity
and evidence Sources; conflict groups require every claim. Those references must
already occur in the original sealed inventory, so no current-row expansion or
arbitrary full-graph prefix ceiling is introduced. Unsupported
operational or recursive definition/view inventory cannot grant authority. No input
record is rewritten to manufacture the raw CAS envelope.

ReadEligibility remembers successfully projected generated definitions for the whole
request. Its final response fence repeats the original decision/full input check in
addition to the existing source head and envelope checks; a changed decision or input
requires retry. This introduces no new mutable proof or historical lookup.

The operational visibility successor accepts the exact withdrawn definition after-image
saved in the canonical receipt. Both backends compare the entire current typed definition
inside the same transaction as view hiding. Native comparison includes all represented
fields and a no-op definition write to conflict with concurrent ordinary updates. Only
active views with a different publication status change; an exact retry returns zero
without updating timestamps. Republished, deleted, missing or changed Hidden generations
conflict, so an old withdrawal retry cannot adopt a later definition.

CanonicalRecord already supplies full typed Definition native/embedded conversion and
generic fieldwise inverse serialization. The physical source-erasure table inventory
already includes Definition, View, Revision and dependency rows; no retained-table or
independent-authority exception is added here.

Authored cases use actual canonical source-less definition commits on both backends,
typed subject authorization, current input mutation and response-fence rejection,
marker-only output refusal, changed output/Hidden refusal, and operational withdrawal
idempotency/Published and Hidden ABA. The withdrawal fixture tests only the narrow
successor and does not manufacture a canonical publication certificate. Formatting and
diff checks are source validation; central integration owns compilation and execution.
