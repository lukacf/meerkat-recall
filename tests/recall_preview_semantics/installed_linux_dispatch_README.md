# Optional installed controlled query dispatch

This source packet is separate from the 19 core installed cases, all semantic
acceptance, and the paid gateway. D froze the exact expectation before candidate
outputs: **three physical embedding POSTs per backend**. No candidate, listener,
artifact, provider, or service has been executed by this source preparation.

The driver inherits the core installed driver's trusted artifact installation,
fresh CLI credentials, no-ambient child environment, Linux offline namespace,
bounded raw HTTP capture and owned process-group cleanup. It uses actual
installed HTTP space/grant/config APIs and retained MCP `search_entities` through
the real approved query embedding client. It does not substitute a tool handler.
Classified space creation, grants and processing replacements use the core's
explicit singleton named bootstrap credentials, with only that space's frozen
policy clearance. Provider queries continue to use ordinary service credentials
and live grants. The global operator has no data clearance and is used only for
runtime management. A missing bootstrap token cannot fall back to it. The
candidate must include C's reviewed classified bootstrap implementation, and all
transitive source hashes require a new D review after this change.

Two independent loopback listeners receive only the original frozen household
and business queries, exact model/dimensions, and distinct synthetic credentials.
Their replies are fixed `[1, 0, ...]` vectors of the configured size. These are
explicit transport spies; empty entity results have no relevance meaning.
Each space has an immutable profile and explicit query/document approval pair;
the installed document embedding path is **not** exercised by this packet.

The frozen chronology is:

1. Household query with the valid single-space household service token: one call.
2. Business query with the valid two-space service token: one further call.
3. Household token selecting business: typed forbidden, zero additional calls.
4. Remove household query approval with current config generation, then call:
   typed provider-unapproved, zero additional calls. Restore the original binding.
5. Revoke that binding, then call: typed provider-unapproved, zero additional
   calls. Restore the original binding again using current generation.
6. Rotate the household connection's credential reference and generation through
   the actual configuration API, preserving the immutable profile and bindings.
   Repeat the original query: exactly one further call using only the new key.

Actual GET configuration readback verifies space ID, policy/level, profile,
account, endpoint, model, dimensions, preprocessing, approvals and generation
before first calls and after every change. The business configuration must remain
unchanged. Fixed finite nonzero responses never supply a predetermined retrieval
winner. A cross-space credential, stale rotation key, extra attempt, original
query rewrite, malformed framing, or unexpected provider operation fails and
retains its private receipt. Unknown authorization values are hashed/redacted;
the known synthetic canaries are recorded verbatim. These are not real secrets.

The two sockets, server threads and accepted connections are owned by the run.
Cleanup interrupts owned accepted sockets before listener shutdown; cleanup is
inside the core failed-observation boundary. HTTP requests and child processes
retain the core limits. Additional limits are 16384 request bytes per spy, a
2-second socket read timeout, and exactly three physical embedding attempts.
The isolated namespace prevents real network/model access. Overall work is
bounded at 300 seconds; bounded cleanup follows as in the core driver. Host disk
capacity remains an allocation prerequisite, not an implied whole-run disk quota.
