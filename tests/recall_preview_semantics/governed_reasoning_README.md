# Final provider policy for verification and adjudication

Support verification and truth maintenance previously applied their local low
reasoning default after `govern_agent_build` had cleared caller provider
parameters and installed the approved space binding. The late assignment reached
the SDK and overrode its medium default, conflicting with the selected gateway
request policy. The other extraction and identity builders already applied local
defaults before governance.

Both affected builders now apply local defaults before the existing authorization
step. Governance remains the single final authority for model, account, endpoint
and provider parameters. No new reasoning setting or state authority is added.
The gateway's fixed reasoning requirements, output-token limits, total budgets,
support verification and truth-maintenance behavior remain unchanged.

New support-verifier identities and the adjudicator decision fingerprint record
the corrected request-policy version. Existing receipts retain their recorded
identity; future decisions cannot reuse a memoization key from the old low-effort
path merely because the model, evidence and prompt are unchanged.

Two regression controls call the active support-verification and adjudication
methods through the real approved transport and SDK, using an embedded space
configuration and one ephemeral loopback HTTP listener each. They inspect the
actual outgoing Responses JSON for medium reasoning, automatic summary, exact
output-token limit, compiled operation schema in the initial system instructions,
and absence of hosted web search.
The fixture returns HTTP 401 after capture, so it cannot manufacture support,
an adjudication verdict, model usage or publication. No ambient credential or
external provider endpoint is used. Listener and operation deadlines are bounded.

The source ordering defect is independently established. Attribution of a
particular closed qualification denial still depends on that run's captured
evidence; this repair does not relabel a failed run or establish relevance.
These controls do not test model quality, live provider compatibility, native
packaging or source publication. Preserve the original failed run and nonce.

The support control runs the production evidence normalizer before verification.
The parser alone leaves the source node unset, so its result has no eligible
support candidate. The control checks that this unbound claim remains
unpromotable, then requires one normalized candidate with the exact source
revision, node and quote. It captures the outgoing request before checking that
the fixture's HTTP refusal fails the verifier and leaves promotion prohibited.
This corrects the original control's missing setup; support validation and
production extraction behavior are unchanged.

The first agent turn exposes its compiled schema through the SDK's system
instruction projection. The control parses that exact JSON and checks the
operation's required fields and types. Native `text.format` belongs to a later
extraction turn, which the initial HTTP refusal never reaches; these controls
make no claim to execute that later constrained-decoding phase.

After the captured refusal, the support control requires its mapped verifier-run
error with no support receipt, while the adjudication control requires the
existing `Ok(None)` fallback with no verdict. A failure before request dispatch
cannot satisfy either control.
