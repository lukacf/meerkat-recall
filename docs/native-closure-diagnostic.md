Native erasure closure diagnostic
=================================

This diagnostic checks the current rows of the already inspected native snapshot
after the existing exact control-retention proofs are prepared. It invokes the
same native classifier that the physical copy invokes. A rejected current row
still fails closed with the same native error variant; its message adds a fixed
table class. Stored record IDs, payloads, dynamic table names, journal keys and
reference tokens are never included in that message.

The physical selector and original maintenance deadline remain unchanged. This
does not repair a surviving erased reference and does not authorize retention of
one. Its immediate purpose is to identify the remaining Surreal independent
status/contact withdrawal failure on the next focused validation of that failed
fixture. The original failure and other running qualification results remain
unchanged. The two new regression cases cover unchanged refusal, exact retained
version handling, historical-row exclusion and bounded diagnostic labels.

Preflight diagnostics apply only when the original journal contains one erasure intent. With multiple intents, exact control retention is a union across authorities, so the original native selector alone decides closure and retains its existing errors. This guard avoids imposing a narrower retention policy during diagnostics. The fixed contact table class is `source_contact_intent`.
