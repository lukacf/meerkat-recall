Predicates are the verbs of Elephant's knowledge graph. Every relationship and attribute uses a predicate to describe what it means -- "works_at", "born_on", "located_in". The predicate registry provides a canonical vocabulary so that different extraction runs, documents, and sources all map to the same concepts.

## Why Predicates Matter

Without a controlled vocabulary, the same real-world relationship might appear as "works_at", "employed_by", "is_employee_of", or "works for." Each variant would create a separate, disconnected edge in the graph. The predicate registry solves this by:

1. Defining **canonical predicate IDs** as the single source of truth
2. Mapping **aliases** from raw extraction strings to canonical IDs
3. Attaching **semantic configuration** that controls truth maintenance behavior

## Predicate Registry

Each entry in the registry represents a canonical predicate:

<CodeGroup>
```rust PredicateRegistry
struct PredicateRegistry {
    base: BaseFields,

    predicate_id: String,              // unique canonical ID, e.g. "works_at"
    description: Option<String>,       // human-readable description
    status: String,                    // "active" or "deprecated"

    semantics: Option<PredicateSemantics>,
    semantics_status: SemanticsStatus, // configured | default | needs_review

    // Usage tracking
    first_seen_at: Option<DateTime<Utc>>,
    usage_count: u64,
    last_used_at: Option<DateTime<Utc>>,
}
```
</CodeGroup>

### Predicate Semantics

Each predicate can carry semantic configuration that drives truth maintenance:

| Field | Type | Default | Description |
|---|---|---|---|
| `temporal_model` | `TemporalPersonality` | `StateOverTime` | How the predicate relates to time |
| `cardinality` | `Cardinality` | `Many` | Whether the predicate allows one or many values |
| `conflict_policy` | `ConflictPolicy` | `AllowParallel` | How competing claims are resolved |
| `recency_basis` | `RecencyBasis` | `SourceEventTime` | Which timestamp drives recency |
| `min_evidence` | `u32` | `1` | Minimum evidence count for promotion |
| `promotion_threshold` | `f32` | `0.7` | Minimum confidence for truth slot selection |
| `partial_resolution_policy` | `PartialResolutionPolicy` | `Defer` | How to handle partially resolved assertions |

<Accordion title="Cardinality">
- **`one`** -- only a single value is valid at any time (e.g., "date_of_birth")
- **`many`** -- multiple values can coexist (e.g., "speaks_language")
</Accordion>

<Accordion title="Semantics Status">
- **`configured`** -- explicitly set by an operator
- **`default`** -- using system defaults, not yet reviewed
- **`needs_review`** -- flagged for operator review
- **`llm_proposed`** -- proposed by the truth-maintenance adjudicator when it resolved a conflict on a predicate with no registered semantics. Never overwrites `configured` semantics; later adjudications may revise it
</Accordion>

## Predicate Aliases

Aliases map raw extraction strings to canonical predicate IDs. When the extraction LLM outputs "employed by", the alias system maps it to the canonical `works_at`.

<CodeGroup>
```rust PredicateAlias
struct PredicateAlias {
    base: BaseFields,

    alias: String,                 // the raw string, e.g. "employed by"
    alias_type: AliasType,         // raw_string | plugin_code | schema_field
    source_plugin: Option<String>, // originating plugin, if any
    confidence: f32,               // 0.0-1.0
    status: AliasStatus,           // proposed | active | deprecated
    scope: AliasScope,             // global | plugin_only | source_type
    predicate_id: String,          // target canonical predicate
    confidence_version: u32,
    usage_count: u64,
}
```
</CodeGroup>

### Alias Types

| Type | Description |
|---|---|
| `raw_string` | A raw string from LLM extraction output |
| `plugin_code` | A code generated by a plugin |
| `schema_field` | A field name from a structured schema |

### Alias Scopes

| Scope | Description |
|---|---|
| `global` | Applies everywhere, across all sources and plugins |
| `plugin_only` | Only applies within a specific plugin context |
| `source_type` | Only applies for a particular source type |

### Confidence Thresholds

Alias confidence gates where the alias is used:

| Threshold | Default | Purpose |
|---|---|---|
| `truth_min_confidence` | 0.9 | Minimum confidence to use the alias in truth maintenance |
| `query_expand_min_confidence` | 0.6 | Minimum confidence to use the alias for query expansion |

## Alias Governance Lifecycle

<Steps>
  <Step title="Propose">
    A new alias mapping is proposed, either automatically by the extraction pipeline when it encounters an unknown predicate string, or manually via the `propose_predicate_alias` API. The alias is created with status `proposed`.
  </Step>
  <Step title="Validate">
    The proposal is validated against existing aliases and predicates using `validate_predicate_proposal`. This checks for conflicts, duplicates, and semantic consistency.
  </Step>
  <Step title="Approve">
    An operator (or automated policy) approves the proposal via `approve_predicate_proposal`. The alias status moves to `active` and it begins participating in canonicalization.
  </Step>
</Steps>

<Note>
Deprecated aliases are retained for historical queries but no longer participate in canonicalization. When an alias is deprecated, truth slots that used it are marked stale for recomputation.
</Note>

## Registering New Predicates

New predicates can be registered via the `register_predicate` API:

```json
{
  "predicate_id": "works_at",
  "description": "Subject is employed by or works for the object organization"
}
```

The predicate starts with `semantics_status: default` and system-default semantics. An operator can later configure specific semantics (cardinality, conflict policy, etc.) based on the predicate's real-world behavior. Alternatively, when [truth maintenance](/concepts/truth-maintenance) adjudicates a conflict on a predicate that has no registered semantics, the adjudicator proposes semantics that are persisted with `semantics_status: llm_proposed`; persisting them emits the predicate-registry outbox event so dependent truth slots recompute under the learned semantics.
