# D28 authenticated startup boundary

`d28_runtime_bootstrap.py` supplies the owned live-service boundary for S's
separately versioned dynamic workload orchestrator. It is a library with no CLI,
execution permission flag or qualification verdict. The planned S entry is G's
actual immediate child and calls:

```python
async with reviewed_d28_startup(plan_reference, expected_launch) as live:
    # S validates complete installed/runtime evidence before any provider cohort.
    # S then owns the original preparation and measurement phases and their bounds.
    original_files = live.original_bytes()
    live.revalidate_custody()
```

`plan_reference` is the existing exact `{path, sha256}` reference to original
read-only `/inputs` bytes. The plan retains C's v1 schema and includes this module
and all transitive helpers in its reviewed hash inventory. `expected_launch` is
the exact existing G expectation object, including original D28 allocation hash
`0a54fcd4c6359e39611567a06857f2d61975b3f19a80052f6ea49691f6d1633f`.
S must bind both to D's original independent static review before this call.
It forwards that exact static `expected_anchor`, including `format` and the
original `caps`, without removing fields. C requires the complete stable set:
`format`, `run_nonce`, `source_commit`, `proposal_sha256`, `corpus_sha256`,
`allocation_sha256`, `artifact_sha256`, `paired_artifact_sha256`, `runtime_sha256`,
`gateway_sha256`, `bindings_sha256`, `bridge_sha256`, `context_helper_sha256`,
`command_sha256`, and `caps`. The D28 caps remain 2,100 physical dispatches and
3,000,000,000 nano-USD. Missing fields, wider caps and added future manifest,
configuration, input-inventory, clock or parent fields refuse. The original
primary `expected_launch` retains its strict earlier shape without `format` or
`caps`, with a null allocation. G still verifies the actual later manifest,
configuration, input inventory and original process/clock custody dynamically;
excluding them from the prior review does not exclude their actual verification.
The adapter does not invent D's nested static schema or accept a `qualified`
flag as permission. The S consumer call and independent predicate review remain
required before this source can be described as an executable qualification path.

The adapter invokes the existing actual CLI credential, authenticated persistent
service/schema and classified two-space/grant/readiness bootstrap. It never calls
the primary collector or opens a provider cohort. Both backend entries use G's
original start and 7,800-second whole deadline. The 300-second startup bound and
75-second cleanup reserve remain inside that allocation. The wall deadline is
the earlier original plan expiration and G expiration. The caller still enforces
D28's original per-preparation and measurement clocks, request/capture bounds and
physical provider allocation; startup does not create or reset those phases.

`live.receipt` is a fresh parsed copy of the original C v1 receipt, always
`qualification_scope: authenticated-clean-persistent-startup-only`,
`qualified: false`, `product_acceptance: false`. Its legacy `artifact_sha256`
and `paired_artifact_sha256` denote executable hashes. An independent validator
must bind archive identities separately; the adapter never renames these fields.
`live.original_bytes()` rereads only original receipt/context/isolation/plan,
saved TOML, process journal and request/response captures with exact hashes.
It returns path-to-original-bytes, preserving whitespace and serialization.
The D/S validator owns typed raw-reference wrappers and the one acceptance
predicate. No JWT, signing key, provider credential or live unfinished log is read
by this evidence collector. Ordinary scoped token **paths** are in
`live.token_files` for S's public requests.

Custody revalidation checks the same actual G parent and owned process identities
before yield, on explicit calls and after successful consumer return. It does
not substitute for current configuration/head/grant checks in the S consumer.
Every exit cleans all original C-owned handles through the existing process
owner and writes separate immutable `cleanup.json` terminal evidence. Startup
bytes remain unchanged after consumer failure, cancellation or cleanup failure.
An incomplete cleanup raises and must suppress the next backend. The original
v1 receipt is never retroactively turned into a terminal or installed pass.

The closed-world test source covers original plan/helper/clock refusal, actual
argument forwarding, immutable receipt/byte custody, startup and consumer
failure, cancellation, process replacement and failed cleanup preventing a next
phase. Every process/socket boundary is mocked. These controls are not installed,
provider, semantic, OS cleanup or artifact qualification.

The additive `runtime_package_bootstrap_evidence.py` producer now captures L/D's
exact current-process, capture-inventory and cleanup-obligation carriers before
D28 yields. `live.custody` holds typed references and original `raw_evidence`.
`live.capture_original_custody()` takes another bounded observation under the
same original clock, at most 16 per backend. It reads and binds original G
anchor/network captures, the actual read-only input inventory, current process
stat/executable identities, complete original request/response captures and
completed CLI log bytes. It brackets process executable observation with exact
PID/parent/group/session/start identity checks. Live unfinished logs remain
terminal obligations. `setup_states` is a supplemental actual-handle observation;
the original v1 command journal and bootstrap receipt remain unchanged.

The evidence-reader aggregate is the sum of already allocated channels:
16 MiB HTTP captures + 16 processes × 2 streams × 4 MiB logs + 4 MiB metadata
= 148 MiB. This grants no additional process, stream, HTTP, provider or elapsed
allocation. It never reads token or signing-key files. The pure validator must
still require original CLI launch identity/terminal signal custody from the
shared process owner, complete installed-offline prerequisite evidence and an
actual effective runtime recipe. Those source gaps are not established by
`setup_states`, saved TOML or this capture inventory. Primary-v2 use of the same
producer awaits the primary owner's exact additional observation seam; existing
primary-v1 input/receipt schemas remain unchanged.

Current-process items retain separate original `stat` and `stat_after` raw refs.
The current bootstrap PID must be this actual producer process. Process observation
time precedes the final controller-wrapper observation taken after all reads;
both consume the same original deadline, with no refreshed allocation.

The actual bootstrap now reads `get_runtime_config` after managed-worker readiness
and retains the complete original MCP capture of `managed_worker_recipe`.
`await live.revalidate_worker_recipe()` makes another authorized read and refuses
a changed construction UUID or recipe hash, keeping the original observation.
Every read uses the existing startup HTTP/capture caps and original run clock.
This establishes actual queue/tree construction values only; per-space provider
retry/preprocessing policy still requires the separate governed-factory evidence.
