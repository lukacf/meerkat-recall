# Original primary bootstrap policies

The independent dynamic validator accepts the original primary corpus's exact
named pairs: `semantics-household` / `synthetic-household` / level 3, and
`semantics-business` / `synthetic-business` / level 7. Earlier bootstrap code
accepted only the D28 policy family, which could not run the already reviewed
primary corpus. The corpus and its accepted binding fixtures remain unchanged.

The primary names and policies cannot be reassigned, swapped, mixed with D28, or
used under another name. A plan requires exactly two distinct spaces and one
complete policy family. The original D28 family retains its existing bounded
names, including historical `household`/`business` fixtures and actual
`qualification-household`/`qualification-business` inputs. Generation, labels,
handling, bindings, capture limits and allocation checks remain unchanged.

A scoped primary wiki plan may explicitly set `scoped_wiki: true`. Only that
marker, the exact primary named policy family, and both explicit `write:entity`
and `manage:wiki` scopes admit the entity-write grant needed to create the
governed definition and compile its article. The marker is true-only; it is
invalid for the workload family. Entity write remains outside core and ordinary
conditional scopes. Static phase inputs and the collector must separately bind
this marker to the reviewed scoped compile cases before using those grants.
The independent static review also binds a marked plan to the primary allocation
(`allocation_sha256: null`); primary space names cannot obtain the grant under a
D28 or semantic140 allocation.

The 16 authored controls exercise the actual static review on both backends,
original corpus identity, retained D28 behavior and rejection cases. They are
synthetic validator controls, not provider, startup or retrieval evidence. Their
execution status is recorded separately by the orchestrator; this source change
does not activate the primary allocation.
