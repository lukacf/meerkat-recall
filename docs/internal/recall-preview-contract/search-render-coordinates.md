# Source and rendered citation coordinates

The source repair preserves the original search citation's `span` and `quote`
meaning: exact bytes in the accepted, caller-supplied source revision. It adds
three required fields to `SearchEvidence` on both scoped HTTP search and MCP
`search_scoped`. The raw and rendered coordinates may differ.

| Field | Meaning |
| --- | --- |
| `source_id`, `revision` | Existing external source identity and caller revision. |
| `span`, `quote` | Existing half-open UTF-8 byte interval and exact complete contiguous raw source cover. |
| `internal_doc_revision_id` | Existing exact internal immutable rendered revision identity. |
| `rendered_span` | Half-open UTF-8 support interval in that immutable revision's full `text`. |
| `rendered_quote_sha256` | SHA-256 of the exact rendered support slice. |
| `rendered_text_sha256` | SHA-256 of the entire immutable revision's rendered `text`. |

Both new hashes are exactly 64 lowercase hexadecimal characters, with no
`sha256:` prefix. There is no duplicate `rendered_quote` or invented `evidence_id`
field. The authorized [immutable revision GET](immutable-revision-read.md)
returns the actual complete rendered text and renderer metadata. Consumers can
slice its UTF-8 bytes using `rendered_span` and verify both hashes. Existing raw
source validation still uses `span` and `quote`; do not apply rendered offsets
to the raw source or treat equal quotations as proof of the same occurrence.

For example, the accepted text
`Mira maintains Helios.  \r\n\r\nMira maintains Helios.\r\n` renders to
`Mira maintains Helios.\n\nMira maintains Helios.\n`. Support for the **second**
occurrence has this citation shape (the internal ID is illustrative):

```json
{
  "source_id": "initiative-42",
  "revision": "A",
  "span": {"start": 28, "end": 50},
  "quote": "Mira maintains Helios.",
  "internal_doc_revision_id": "doc_revision:<actual-uuid>",
  "rendered_span": {"start": 24, "end": 46},
  "rendered_quote_sha256": "837d5285260451e0480c01b1c4ec8e1120acdd6821a8342f4d71fe8ea1392c31",
  "rendered_text_sha256": "d46236961ccf38554c1321df0caccf6dbb4bdf92afda489d58886bfa4eca4bbc"
}
```

The renderer's shared deterministic transform supplies the smallest contiguous
raw cover of the selected rendered interval. This retains raw CRLF or trailing
spaces removed *inside* that cover; raw and rendered quotes need not be equal.
A generated terminal LF can extend rendered support while adding no raw bytes.
An interval made solely of generated bytes refuses: it has no original source
support. Every endpoint must remain a valid UTF-8 byte boundary. Substring search,
first-match selection, clipping, trimming and guessed identity mappings are not
valid coordinate conversions.

The active consumer must verify the original accepted source bytes and declared
hashes, exact renderer name/version/configuration, full transformed rendered
bytes and immutable revision hash, original completed-publication proof, both
intervals, and current ancestor authorization. It must retain the reader's final
original-observation verification after mapping. A transform alone establishes
neither current publication nor access authority. Unknown transforms and failed
proofs refuse through typed errors; they cannot fall back to guessed offsets.

The entire encoded response still has the original **262,144-byte** ceiling,
including the added fields, raw quotation expansion and JSON escaping. The
existing selected-response measurement enforces this cap and never truncates
support. The existing consumer-chosen one-time limit 20→10 retry remains; the
original oversized request still has `retryable:false`. Independent fixture
arithmetic must include the new fields rather than reuse an older response size.

This wire checkpoint must be integrated with the search owner's active evidence
constructor and grounding's shared renderer mapping. The DTO alone is not a
completed product repair. D's independent literal coordinate fixture at
`4d6670edc15235d2510693ce8cefc0571a3c94f8` (original JSON SHA-256
`54138704a332d6e275dc434ad0d6456f49107a811c08ea9abbafdbd68171dc3b`)
provides expected CRLF, whitespace, repeated-phrase, Unicode and synthetic-LF
cases. Source review, actual runtime execution, consumer adoption and semantic
qualification remain separate. The already delivered 14-case OB3 fixture packet
at `753e44e` is preserved unchanged; this is an additive source-contract notice.

`tests/recall_preview_semantics/render_coordinates_http.rs` is the mounted HTTP
verifier called by the same actual publication fixture used for the MCP oracle.
For each literal case it compares the returned citation with the independent
raw/rendered coordinates, reads the cited full immutable DTO through its public
route, verifies exact bytes/renderer/hashes, and requires missing-raw-scope and
foreign-space denial. It uses an injected ordinary, non-bypass principal; signed
JWT middleware qualification remains a separate test family. Sharing the actual
published fixture avoids a second source submission. The repeated-phrase case
uses actual semantic node selection with fixed transport-spy vectors, because
lexical search retains the first eligible chunk per document. Its MCP and HTTP
positives each make exactly one governed query embedding; the post-tamper MCP
negative makes one more. The other six cases remain lexical with no query
provider calls. These controlled vectors prove coordinate plumbing, not model
relevance. All original expected byte offsets and quotations remain unchanged.
