# Full workload source contract

This separate inactive contract gives G finite fixture and oracle requirements
for new `full_workload_*` driver paths. D owns `full-workload-contract.json`.
The original50-source/200-call D28 corpus, metrics and allocation are unchanged.
Full functional qualification adds two exact2MB inputs and four independent
shared-support inputs:56 distinct sources,28 per named space. Limit+1 refusals
are not accepted sources; subsequent no-op/revision/lifecycle phases reuse these
identities. The full source bytes are specified by a deterministic ASCII recipe
and independent SHA256 values, not generated by a model.

Fourteen explicit phases cover configuration, actual preparation, source size,
shared support, semantic-intent retry, blocked extraction races, competing CAS,
real public backlog states, permission/retraction distinction, provider revocation,
140 callers, consumer size fallback and Recall outage. Functional source can use
controlled owned spies; it must say precisely which evidence they establish.
The140-call functional phase uses lexical search. Actual semantic concurrency,
latency and relevance require a separate budget and threshold contract before
execution; neither existing provider allocation may be reused. Per-backend
limits include1800seconds,8000public calls,4096ownedspy dispatches and1GiBcaptures.
All provider/network/service execution remains disabled in the checked-in contract.

G must map each expectation to supported public routes and report unavailable
private manifest/vector/physical deletion proof as unmet. A marker or404 cannot
supply those proofs. Deterministic spy controls may hold/release original responses,
not mutate internal queue/head/receipt authority. FW13/FW14 require actual OB3
consumer observations; a Recall driver cannot certify them. The exact read-only
expectation manifest remains D custody while G implements the new source adapter.
