# Independent Graph recipe proposal

These literal inputs and expectations were authored separately from the public
Graph fixture and workload drivers. Qualification must review the exact manifest
and file hashes before use. This package authorizes no execution and reports no
product acceptance.

`manifest.json` maps each case to a complete `recall-public-graph-fixture/v1`
file, with both the file SHA-256 and the canonical JSON SHA-256 consumed by the
existing Graph helper. The 24 workload files preserve the original 50 corpus
sources and reuse the same six additional source identities: `full/large` and
`full/shared/a`, `full/shared/b` in each of the two named spaces. The two maximum
size recipe files each retain all two million original bytes and all expected
rendered bytes. Load them separately within the existing eight MiB per-file cap;
do not inline them into a single plan.

The original corpus is not edited. Replacement sources append one fixed sentence
to the exact original text, and their extraction expectations cover that explicit
new sentence. Both competing atlas-03 requests must bind the same original
observed generation. New sources require absence; replacements require the
captured original public generation. Keep the independently pinned template
immutable, deep-copy it for the one generation binding, and retain both template
hash and actual wire request. Rehashing that request does not approve new source
text, envelopes, evidence, or model responses.

The shared notebook sources preserve both fixed facts: Mira maintains the Helios
shared notebook, and its access code is the literal `violet-47`. Each source must
complete actual Graph publication. Shared entity/relation identity and support
survival after one source is removed must be observed through the supported
product paths, not inferred from two successful source acceptances. Unknown
promotion or identity-resolution calls remain an unmet preparation prerequisite.

The two million byte Graph replacements use the exact existing large-input
recipe and its original SHA-256. They expect only the independently fixed first
and final statements. Other catalogue-only extraction windows return an explicit
empty assertion set. The final quoted sentence is unique: the model response
supplies a zero-based local span, and the product's existing exact unique-quote
normalization finds its real position within the selected window. The expected
global span remains literal in the recipe. No observed candidate output supplies
semantic expectations or global coordinates.

`workload-spy.json` and `container-spy.json` pin source selectors, complete
extraction outputs, full independent support tuples, original call schedules,
and synthetic credentials. They contain 2,210 and 181 maximum physical calls,
respectively, within the existing shared 4,096-call ceiling. Those per-rule
limits are ceilings, not expected successful call counts or retry authorization.
First calls for FW06, FW07, FW09-running, and FW11 are held. FW09-retryable and
FW11 return controlled 503 responses. Actual public operations must establish
Running/pending/failed_retryable; spy holds and elapsed time cannot substitute.
FW11 revokes the current binding while the original first request is held,
releases that original 503 response once, and requires zero subsequent sends.

The installed container positive fixture is explicitly default-policy level 0;
it cannot qualify the separately classified household/business workload.
CC04 requires a real positive exact-revision lexical result before the absent
query. CB09 requires actual complete indexed publication before current query
profile revocation and zero subsequent sends.

The original CB07 contract requires one complete original quote of at least
262,145 bytes. The ordinary installed planner uses a 3,000-token window with a
0.25 token-per-byte estimate, limiting every selected window to 12,000 bytes.
`container-oversized-unmet.json` retains that literal requested source and quote
for review, but it has no executable extraction rule and must remain **unmet**.
No collector-cap change, truncated quote, fabricated receipt or forced HTTP 413
can satisfy it. The coordinator approved a separately reviewed whole-response alternative.
`container-response-budget-0.json` and `container-response-budget-1.json`
supply 20 independently grounded claims across two sources. Each source has ten
paragraphs of exactly 6,500 bytes, each with 3,000 embedded U+0001 bytes. The
complete source text encodes to about 215 KiB, keeping full Source, Doc and
immutable revision responses within the original 270,336-byte collector cap.
The default planner can select each paragraph, while two adjacent paragraphs
exceed its window. JSON escapes preserve every byte. The fixed lexical query
`oversees` occurs in claim predicates and document text, not entity names.
With at most two selected document chunks, 20 results include at least 18 full
claim quotes: the quote strings alone encode to 387,036 bytes. Ten full claim
results plus exact coverage have a conservative 221,584-byte bound. Padding
contains frequent sentence boundaries, preserving bounded ordinary chunks; no
unsupported long sentence is assumed to fit the configured chunk size.
`container-response-budget-arithmetic.json` pins these calculations and the
actual selection prerequisites. Qualification must freeze the revised contract
and review these literal bytes before use. The old single-quote case stays unmet.

The response arithmetic includes the frozen required `rendered_span`,
`rendered_quote_sha256`, `rendered_text_sha256`, and `doc_id` fields. Existing `span` and
`quote` retain their supplied-source meaning. Both hashes are 64 lowercase hex
bytes, and the existing immutable revision ID identifies the full renderer DTO;
the parent document ID comes from the same authorized current document and has
the exact `doc:<UUID>` form (40 ASCII bytes, 42 bytes as a JSON string). The ninth
evidence field adds 52 bytes to each result and 56 bytes after MCP text escaping;
the wire does not duplicate the complete rendered quote. Ten results include
a conservative 32-byte encoding allowance for each finite score. MCP wraps the
complete `{"ok":true,"data":SearchResponse}` tool envelope as text. That inner
envelope has a 221,603-byte bound and must pass the separate 262,144-byte tool
limit. Its additional escaping is counted separately, giving a 252,277-byte
JSON-RPC bound with a 20-digit request ID. A further 4,096 bytes reserved for
stream framing gives 256,373 bytes, within the original
270,336-byte collector ceiling. Actual full framing and evidence must still be
captured and checked; these calculations authorize no runtime acceptance.

The recipe controls are closed-world Python only. They check original hashes,
byte spans, immutable corpus prefixes, complete semantic tuples, held call
selection, source count and deliberate CB07 refusal. They do not exercise a
service, database, provider, model, native concurrency, or installed artifact.
