## Overview

Meerkat Recall uses system-level scenario tests to root out integration issues. Each scenario specifies the environment, principal, and explicit invariants that must hold.

Scenarios are organized into groups:
- **S1.x** -- Baseline CRUD (entity/relationship lifecycle)
- **S2.x** -- Integration Hell (merge, rollback, redaction)
- **S3.x** -- Extension readiness
- **S4.x** -- Assertion pipeline (extraction, truth maintenance, budget)
- **S5.x** -- MCP and API integration (document ingestion, search, tools)
- **M1-M10** -- Cross-cutting concerns (isolation, startup, queues, truth)

## Running Scenarios

<CodeGroup>
```bash All scenarios
./scripts/repo-cargo test -p elephant-scenarios -- --nocapture
```

```bash Full E2E suite
./scripts/repo-cargo test-e2e
```

```bash List scenario names
./scripts/repo-cargo test -p elephant-scenarios -- --list
```
</CodeGroup>

<Note>
  The scenario harness uses SurrealDB's `kv-mem` backend. Some test lanes elsewhere in the workspace require live services or credentials. `test-e2e` excludes named live-LLM tests; the broader `integration` alias runs all ignored tests and can invoke paid providers. Inspect the selected tests before opting in.
</Note>

## S4.x -- Assertion Pipeline

| Scenario | Name | Verifies |
|----------|------|----------|
| S4.1 | Progressive Triage | Mode selection: skip (duplicate), metadata (low-value), retrieval (text), graph (entities) |
| S4.2 | Assertion Lifecycle | End-to-end: extraction from doc_revision, resolution, canonical commit |
| S4.3 | Predicate Governance | Predicate proposed state, alias creation, approval workflow |
| S4.4 | Truth Maintenance | Conflicting claims detected via truth_slot grouping; resolution strategies applied |
| S4.5 | Budget Enforcement | Daily budget limits; over-budget rejection; mode downgrade from graph to retrieval |
| S4.6 | Temporal Supersession | Validity windows; newer claims supersede older; expired claims excluded |
| S4.7 | Abstention Retry | Ambiguous resolution triggers Abstained; exponential backoff; max attempts to Failed |
| S4.8 | Staged Commit | Work artifacts written first; atomic commit to canonical tables; retry on failure |
| S4.9 | Freshness Sweep | Freshness decay; sweep recalculation; demotion below threshold |
| S4.10 | Reprocessing | Reprocess job with selection criteria; old revisions superseded; budget pacing |
| S4.11 | Massive Document | Documents with >100 nodes trigger partitioning; cross-partition links maintained |
| S4.12 | Implicit Now | Claims without explicit time default to extraction time; TimeRefinement handling |
| S4.13 | Outbox Triggered | NewAssertion triggers slot allocation; ConflictDetected triggers resolution |
| S4.14 | ABAC Inheritance | Derived artifacts inherit max security level; labels union across chain |
