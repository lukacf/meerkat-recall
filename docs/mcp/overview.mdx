Elephant exposes knowledge operations through MCP over Streamable HTTP. An
agent can discover tool schemas, submit evidence, search the graph, and inspect
cited context using the caller's space and permissions.

## Connect

Start a server using the [quickstart](/quickstart), then configure your client's
**HTTP MCP** connection with:

```text
http://localhost:3000/mcp
```

Send `Authorization: Bearer <token>` when authentication is enabled. The token
must select the intended space and authorize the requested operations. In local
`SKIP_AUTH` mode, `X-Space-Id` selects the development principal's space.

`elephant serve` runs an HTTP server. The separate `elephant-local-helper` is a
stdio service for client-side file ingestion. The server's Full-profile file
tools read paths on the **server**; the helper reads paths on the **client**.
See [ingesting data](/guides/ingesting-data) before choosing either path.

For remote connections, configure `MCP_ALLOWED_HOSTS`; browser clients may also
need `MCP_ALLOWED_ORIGINS`. These are transport protections, separate from data
authorization. See [deployment](/operations/deployment).

## Choose a profile

A profile limits the available operations. It does not grant permission to
perform them. Use `tools/list` on the connected endpoint to discover its current
schemas; runtime state and authorization can further restrict the surface.

| Endpoint | Use it for | Important boundary |
| --- | --- | --- |
| `/mcp` | Everyday ingest, discovery, entity context, provenance, and timeline access | Curated tools; does not include all document or assertion reads |
| `/mcp/agent` | Read-only graph and evidence access, including extraction agents | No direct writes or runtime configuration |
| `/mcp/maintenance` | Read tools plus identity, predicates, wiki, source freshness, and maintenance operations | No general document ingestion or entity creation |
| `/mcp/full` | Operator and application integrations needing the complete core registry | Requires the same data authorization as other profiles; not a superset of every Default-only convenience handler |

The internal Pipeline profile provides work-queue operations to Rust callers;
there is no `/mcp/pipeline` HTTP endpoint. Per-tool profile labels live in the
[tool reference](/mcp/tools).

<Warning>
The Default-only `get_provenance` convenience handler currently checks scopes
and space but does not authorize every returned claim and evidence record.
Restrict its use to trusted callers entitled to all content in that space.
Do not use it as a clearance-filtered evidence API. See
[security boundaries](/concepts/security#authorization-boundaries).
</Warning>

## Check readiness before ingesting

Call `get_runtime_status` with `{}` first. It remains available even before
storage is configured.

| Observed state | What it means | Next action |
| --- | --- | --- |
| Cannot connect | No usable transport connection | Check the process, URL, proxy, and transport host settings |
| `bootstrap_mode: true` | No effective runtime configuration | An eligible administrator can use `initialize_runtime` with its discovered schema |
| `configured: true`, `semantic_ingest_ready: false` | Configuration exists, but semantic ingest is unavailable | Inspect `issues`, storage, workers, and extractor readiness |
| `semantic_ingest_ready: true` | The semantic ingest gate is open | Rediscover tools, then submit evidence and track processing |

Runtime environment settings such as `ELEPHANT_DB` or `SURREALDB_URL` select
configured mode. They do not automatically make the extractor ready. If the
extractor connects to Elephant's own `/mcp/agent`, startup retries after the
listener binds; a brief initial `extractor_ready: false` can be expected.

Ingest tools are hidden while semantic ingest is unavailable. Configuration
reads and writes have separate permission checks: `get_runtime_config` requires
system read or write permission, while `configure_runtime` and
`initialize_runtime` require system write permission (or development bypass).
The Agent profile only exposes runtime status.

## Make a call and interpret the result

After MCP initialization, this is a `tools/call` request body:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "search_all",
    "arguments": {"query": "Project Cedar", "limit": 5}
  }
}
```

An MCP client library normally handles the protocol envelope. Tool reference
examples show only the `arguments` object.

Elephant has several result layers. Check each layer instead of treating a
successful HTTP request as a successful operation:

1. A transport or JSON-RPC error means the request failed before a usable tool
   result was returned.
2. An MCP result with `isError: true` means dispatch or execution failed. Read
   its content for the error.
3. Many core handlers return JSON in a text content block using the following
   Elephant envelope. Check `ok` before consuming `data`.

```json
{
  "ok": true,
  "data": {}
}
```

Absent optional fields are omitted. For an Elephant-level failure, `ok` is
`false` and `error` contains the reason; do not require null-valued optional keys.
Runtime-control tools return their own JSON response directly; do not require
this envelope for `get_runtime_status` or configuration calls. Consult the
specific tool for its data shape.

Search results are scoped and filtered. An empty bucket can mean there is no
match visible to this principal. Unified search can also report per-bucket
errors; inspect them before interpreting an empty result as absence.

## Use the Rust dispatcher

Embedded callers can invoke the same handlers without HTTP. They must supply a
trusted principal and configured storage; these constructors do not authenticate
users or supply the managed server's runtime-control tools.

```rust
use elephant_mcp::create_default_dispatcher;
use elephant_policy::Principal;
use elephant_storage::StorageClient;
use serde_json::json;

async fn search(
    storage: StorageClient,
    principal: Principal,
) -> elephant_mcp::McpResult<serde_json::Value> {
    let dispatcher = create_default_dispatcher(storage, principal);
    dispatcher.execute("search_all", json!({
        "query": "Project Cedar",
        "limit": 10
    })).await
}
```

Other constructors include `create_agent_dispatcher`,
`create_maintenance_dispatcher`, and `create_dispatcher` for the Full registry.

Continue with [MCP workflows](/mcp/workflows) for complete tasks or use the
[tool reference](/mcp/tools) to look up arguments. Application code that needs
HTTP status codes, resource routes, or SSE can use the [HTTP API](/api/overview).
