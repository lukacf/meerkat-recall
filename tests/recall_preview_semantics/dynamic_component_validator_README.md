# Original dynamic component validation

`dynamic_component_validator.py` supplies the pure `validate_static`,
`validate_runtime` and `validate_prepared` interfaces. D's independent
`DYNAMIC_COMPONENT_CONTRACT.md` controls their scope. No component establishes
full product acceptance or terminal cleanup of the current persistent services.
Exact original source review and the complete original evidence remain required.

`validate_static(reviewed_static, raw_evidence, backend)` returns a detached
original bootstrap plan. It creates no runtime or provider authority. The other
interfaces retain the independent contract's argument order. `raw_evidence` is
an immutable caller-owned `Mapping[sha256, bytes]`; the validator opens no file,
reads no clock, and performs no process or network operation. Every selected
lookup checks original kind, exact size and digest. Callers may resolve original
read-only files lazily; they must not materialize the provider's 20 GiB disk
ceiling. The cache bound is 256 MiB, runtime reachable evidence 352 MiB, current
capture 148 MiB, and original offline capture 96 MiB. These are bounds on
retained evidence, not new execution or eager memory allocations.

The runtime component verifies the original C bootstrap protocol, actual named
configuration records, saved backend paths, current G namespace/process/input
identity, original clocks, actual worker construction and governed provider
recipes, and original process custody. M's separately reviewed pure
`installed_evidence_validator.py` supplies the complete installed 19-case and
shared process predicates. Its four-field installed identity covers source,
archive, Recall executable and backend. The current runtime separately proves
its paired executable, runtime recipe and controller. Original startup receipts
remain immutable and unqualified; current persistent cleanup remains owed.

Static checks independently enforce both original classified creation requests,
the bounded service scope allocation and reviewed helper paths. Original setup
evidence must contain exactly the seven scoped credential issuers and the
backend's expected service/schema commands. Runtime checks replay each sole
space creation and every grant creation, revocation and restoration with its
original generation CAS and immediate readback. Recorded check names alone
cannot establish those transitions. The original isolation record is bound to
the same gateway namespace; original deadline conversion has no added slack.
Both work-kind lists must be empty in the actual constructed worker recipe,
matching the independently reviewed unrestricted fixture.

The reviewed controller policy requires all fifteen stable original anchor
fields. Final manifest, configuration, input inventory, clock and parent facts
are checked through the original dynamic custody chain; they cannot be supplied
as future static expectations. Recall's archive and executable remain distinct.
The legacy `paired_artifact_sha256` field names the paired **executable** digest,
which must agree across reviewed identity, bootstrap plan and actual anchor.
That field establishes no paired archive provenance.

Preparation preserves the original validated runtime evidence/component and the
original validation time sampled before any cohort or submission. Its separate
current-custody record retains actual later stat brackets and authorized worker
and provider recipe reads. All fifty original typed submissions have prior
absence reads and one durable intent per request. Complete operations, current
heads, Source, Doc, immutable DocRevision, complete node inventories and pipeline
coverage are checked against D's original raw corpus and independent rendered
map. Raw hashes remain distinct from rendered hashes; only root spans contain
the final LF. Configuration changes are limited to the storage content epoch
and updated timestamp. F's separately reviewed `provider_evidence_validator.py`
checks original closed-cohort accounting, captures, no-refund reservations and
finite limits. Missing either helper or any actual evidence refuses with a
static `dynamic_*` ValueError.

Before calling F, preparation validates the original read-only accounting
channel. The seven-field v2 carrier retains typed references to G's unchanged
sidecar, original mountinfo, original directory observation, original export
index and the exact saved preparation caller manifest. Its anchor, source pin,
directory identity and private permissions must agree. The mount table must
show one matching device at `/gateway-accounting`, with per-mount `ro` and no
`rw` or nested shadow mounts. G's source-pinned acquisition performs the
effective-user check; the legacy controller has no UID field, and L invents
none. These observations establish reviewed acquisition and cross-checks, not
a cryptographic guarantee against a malicious observation process.

The caller's raw bytes retain their exact reference hash and length. Separately,
G's canonical encoding of that original parsed caller must match the index's
caller hash and the same candidate, phase intent, immutable inputs, credentials
and bridge.
Every channel record must occur in the bounded original inventory, including
the caller saved outside the preparation output directory. Index membership
must exactly cover the eight original bundle records and all five retained
files for each dispatch. Paths, kinds, lengths and hashes are checked one
bounded record at a time through the caller's lazy Mapping. The existing 20 GiB
disk and 256 MiB cache ceilings remain unchanged. The provider bundle and F's
API remain unchanged.

Current custody uses `recall-dynamic-current-runtime-custody/v2`, with current
process/capture/cleanup references and exact original worker/provider request
and response pairs. `recall-dynamic-runtime-chain/v2` binds the original
component, original evidence, original validated clocks and that current
custody. The passed components retain all mandatory proof limits: public node
markers are not raw vectors, public reads expose no private manifest, cohort
accounting does not fabricate per-request attribution, and fixture preparation
is not semantic relevance or measured load qualification.

Each current worker/provider request and response must occur in the current
capture inventory itself; presence in the union with earlier captures is
insufficient. All original startup and current request records require the
actual integer port 43130. Parent/controller process fields retain the exact
original five-field integer schema, and all network namespaces retain Linux's
`net:[digits]` representation. Independent negative controls preserve otherwise
valid original bytes in a different inventory to test this membership boundary.

The local controls exercise original bytes and immutable lookup behavior,
process identities, strict parsing, classified publication lineage, all fifty
independent rendered fixtures, bounded configuration changes and forged-summary
refusals. Additional controls change original classification, scope, helper,
credential, grant CAS, worker-instance and isolation facts, and check that lazy
file errors cannot expose private paths. They do not execute Recall, providers or installed artifacts, and do
not supply a product-acceptance receipt. Runtime/prepared positive integration
still requires the coherent C/F/G/M/S producer and predicate family plus D review.

A synthetic composition control now feeds complete original installed and
current-runtime evidence through the actual M and L pure predicates. It does
not replace either predicate with a passed result. The control binds separate
archive/executable identities, all scoped issuers, original process events,
grant CAS transitions, constructed worker/provider recipes and live cleanup
obligations. Altered original bytes, current process births, installed candidate
identity and a one-nanosecond extension of the whole deadline refuse. This
establishes source composition only; it is not a real installed/runtime run.

Separate synthetic channel controls compose the actual L custody predicate
with F's actual provider predicate, without replacing either result. Mutated
original directory, mount, helper, cohort, caller or file membership facts must
refuse. A further synthetic control feeds all fifty original fixtures through
the full `validate_prepared` API for both backends: actual M/L runtime predicates, all 454 retained
public request/response pairs, immutable revision and node lineage, later
worker/provider/process custody, original channel and F provider predicates.
It repeats the same evidence at a later premeasurement sample and tests changed
original submission, publication, caller and current-worker records. No
predicate is replaced with a passed result; no real service or provider runs.
The composition also requires preparation's own evidence reader to register
the same verified original runtime capture inventory before resolving the
controller's path-bound network records; runtime replay has a separate reader.
The native transcript additionally retains the original paired executable and
live process obligation, explicit terminal migration command, actual native
configuration paths and the unchanged previous embedded cohort ledger prefix.

The runtime and subsequent current-custody envelopes now require the exact D
`outer_launch` reference. Its bounded wrapper retains the original G manifest,
original launch specification and the same current-process input inventory.
The two raw files must occupy their fixed read-only capture paths and every
member must occur in the corresponding inventory. Both raw hashes bind to the
original full anchor; command and bindings use G's original canonical hashes.
Current custody must retain the initial wrapper and member identities.

The pure predicate independently checks the three existing G manifest variants,
original finite D28 pins, gateway endpoints, account/capability/profile bindings,
exact launch shape, command, permitted bounded environment and input inventory.
It does not read approval files, mount paths, launch a process or infer a new
source-commit field. The original 15 static anchor fields remain unchanged.
Synthetic runtime and complete preparation chains for both backends include
original manifest/spec bytes with whitespace preserved. Focused controls keep
valid evidence elsewhere while removing current membership, change semantic
fields behind freshly calculated raw hashes, and reject reserialization or a
replacement current wrapper. Parent/process/namespace controls require the
specific predicate error, so unrelated later failures cannot satisfy them.
