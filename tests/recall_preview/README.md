# Independent Recall preview qualification

This directory owns expected outcomes and test source independently of product
implementation. No file here is a passing acceptance receipt. The initial source
base is `f59e6f5c99ed095a015656626f4d32c106c13075`; the original audit predates it.
PR22 token verification, entity CAS, retained-history and native packaging repairs
are reused. The transferred F01 patch was unqualified; its successor source needs
its own executed evidence.

`matrix.py` inventories 39 required cases across both supported backends, two
named spaces, retained wiki/lifecycle and the native/container deployment shapes.
An unmet prerequisite, skipped test, fixture, healthy process or compiled binary
cannot satisfy an execution gate. HomeCore and OB3 own consumer implementation
and adoption; their evidence is separate from Recall source qualification.
The inventory distinguishes D-owned oracle source from related peer-authored
tests reviewed by D, with exact source checkpoints for the latter. Provider spies,
random-vector rejection, original-claim retries and usage-completion fixtures
therefore remain visible without being promoted to independent runtime passes.
`GATE_DISPOSITION.md` maps all 39 gates to ready offline harnesses, missing source
work and the artifact/provider/consumer evidence needed for execution scheduling.

The HTTP collector retains exact bounded body bytes as base64 alongside the
parsed response and digest. Short Content-Length, incomplete chunked framing,
oversize bodies, duplicate JSON keys and non-finite numbers cannot qualify a
result. A failed or oversized response retains a bounded prefix explicitly
marked incomplete; its hash is never evidence of a complete response. Offline
tests exercise the actual standard-library HTTP parser without opening sockets.

lineage before preparation. It never inserts a resolved winner, source head,
attempt fence or completed receipt to stand in for the production decision. A
fixed Oriole interpretation is approved through the actual verifier protocol;
negative cases first prove that the valid input can prepare, then change its
evidence or semantics. This prevents a missing support receipt from making every
negative case pass vacuously. Planning writes no live canonical rows. Source and

## Frozen corpus and expectations

`corpus.json` contains synthetic household and business records with unrelated
policies, providers, models, dimensions and extraction guidance. Their fixture
provider names are deliberately not real providers. This avoids representing a
deterministic test double as paid-model semantic evidence. The same external
source key occurs independently in both spaces. Revision changes, a withheld
snippet, an independent corroborating source, lexical distractors and a no-support
query make stale or fabricated evidence observable.

The retained generic `fixtures.py` generator produces 50 structured sources per
explicit named space; it is not the frozen D28 corpus of 50 total sources. It also
generates ASCII and multibyte texts at 1,999,999, 2,000,000 and 2,000,001 UTF-8 bytes.
The accepted contract counts **2,000,000 UTF-8 bytes**, independently of bounded
JSON metadata overhead. A separate 1.1-million-character fixture can exceed that
byte limit when multibyte; do not confuse the consumer's character report with
the API byte contract. Degraded sources cannot become ingest requests. Repeated
observations are not revision ordering; observation timestamps are excluded from
the public immutable retry fingerprint.

Expected-query revisions describe the final corpus state after authoritative
replacements have completed. Pending-state tests use explicit requested/desired/
published coverage and cannot reuse the complete-state oracle. These query
expectations and thresholds are authored proposals for independent/consumer
review, not a measured relevance benchmark. Do not lower them after observing a
candidate merely to produce a passing score; version and explain any reviewed
expectation correction.

`semantic-expectations-approval.json` freezes D's independent pre-execution review
of the separate semantic helper's versioned corpus. It binds the exact corpus
digest and evidence-ranking interpretation after quote-context corrections.
It is an expectation approval only; no provider/evaluator success or consumer
agreement is inferred from the seal.
