# Complete citations and bounded semantic discovery

Source checkpoints: search `a7f72c6bd8e928f33a40845bdd60d0835bbc5762` and selected-response budget correction `de6cdf15796e452bd80f0e72879e6667e0a89bcd`. This supplements the HomeCore C10 and OB3 scoped-search contracts after its dependency group is integrated. It is source-complete behavior with authored tests, not a passing runtime, relevance or provider qualification result. The original request and citation field meanings are preserved. The separately joined [render-coordinate repair](search-render-coordinates.md) adds explicit rendered-span and hash fields.

A citation contains the **complete validated support span** and the exact text at its half-open UTF-8 byte offsets in the immutable supplied revision. Claim text is complete as well. Recall no longer returns a 1024-byte prefix in place of support whose later predicate, date or negation matters. The required `internal_doc_revision_id` remains distinct from the external source and consumer revision. Entity display names may still be shortened; their citation support is complete.

The entire encoded scoped-search response remains bounded at **262,144 bytes**, across HTTP and MCP. If the selected results and coverage exceed this encoded budget, the response returns `413 payload_too_large` on HTTP, or the corresponding typed MCP error. The server does not silently replace selected evidence with an unrelated excerpt. An oversized lower-ranked candidate does not itself poison a higher-ranked answer that fits: full support is retained through selection, then the selected encoded response is measured. Coverage-only responses use the same cap, and JSON escaping counts toward it. Exact citation bytes alone do not prove that a claim is entailed or that the provider ranked it well.

Semantic discovery initially reserves up to 400 raw hits per accessible partition, sharing at most 4,096 raw slots across at most 64 partitions. A full window is not exhaustion: hidden, label-mismatched or unrequested-source hits can occupy it. The engine widens relevant full windows until the requested authorized, deduplicated rank can be established or the bounded budget is exhausted. Ties and full windows without a usable score boundary do not establish a finished rank. Exhausted partitions retain their reservations, so the budget is conservative.

If the rank cannot be established within those limits, HTTP returns `429 rate_limited` (MCP returns the same typed error), rather than a falsely complete empty result or lexical substitutes. A provider/configuration failure remains its own typed error. Once ranking succeeds, revision coverage still follows the current-operation rules in [revision reacceptance](revision-reacceptance.md); ranking completeness does not certify a pending publication.

The search owner's authored positive regression places 401 higher-scoring unrequested chunks ahead of the requested target in the same partition. Its 400-to-800 window fits the budget, so it must return the target using one query embedding dispatch; an error does not satisfy that positive test. Independent qualification owns separate hidden-label and long-claim counterexamples. Their execution receipts remain pending.
